## 阶段 1：genBlockList
- genBlockList 是独立模块/Java 程序，不依赖 Minecraft 和 NeoForge。
- 扫描 src/main/resources/assets/brfurniture/textures/block/*.png。
- 取文件名去掉 .png，得到 ID 列表，例如 level0_wall.png -> level0_wall。
- 输出到 codegen 模块中的 Java 类，例如 DefaultBlockIds.java，存 List<String>。
- 不要输出到 generated 模块。
- 默认列表用于运行时配置缺失时创建默认配置文件。

## 阶段 2：运行时配置加载
- 路径：config/brfurniture/blocks.txt。
- 缺失：用 DefaultBlockIds 创建默认配置文件。

- 每行一个方块 ID，忽略空行和以 # 开头的注释。
- 防御性编程：加载配置文件无论如何都不能让游戏崩溃。
- 校验项至少包括：

    - 内部重复 ID。
    - 与已有注册名冲突。
    - 其他你认为必要的校验。
- 非法、重复、冲突项：跳过并收集警告。
- 警告屏幕：若当前 NeoForge 版本有可用 API，则显示哪些无法读取、哪些 ID 重名，并提示删除 config/brfurniture/blocks.txt 可能解决问题；否则降级为日志。不要强依赖不确定 API。

## 阶段 3：方块注册
- 在 mod 构造阶段读取配置并完成注册。
- 使用 DeferredRegister。
- 每个 ID 注册一个实心方块，并注册对应 BlockItem。
- 注册名：brfurniture:<id>。
- 贴图引用：brfurniture:block/<id>。
- 主类中提供类似接口：
  putBlock("level0_wall", Block::new);
  putBlock("level0_wall", BlockBehaviour.Properties.of()...);
  用两个 Map 分别保存 Supplier<Block> 和 BlockBehaviour.Properties。
  未提供时默认使用 Block::new 和默认木质属性：
  BlockBehaviour.Properties.of()
  .instrument(NoteBlockInstrument.BASS)
  .strength(2.0F, 3.0F)
  .sound(SoundType.WOOD)
- 变种方块：
    - 展墙 exhibition_wall，参考 example_code/TextureWall.java，注册参考 example_code/BackroomsGeneralBlocks.java。
    - 展墙墙根 exhibition_wall_brace。
    - 注册 ID：brfurniture:exhibition_wall/<id> 和 brfurniture:exhibition_wall_brace/<id>。
    - 主类提供 putExhibitionWall / putExhibitionWallBrace。
    - 注册后打包成 Map + List<BlockItem>，例如：
      "level0_wall": { solidBlock, exhibitionWall, exhibitionWallBrace }
- 如果示例文件未提供，先索要，不要猜。
